目标是交付可安装、可独立运行、可持续使用的桌面阅读产品。网页原型通过某项测试，不等于整个 App 已经交付；下表保留所有已提出的功能与验收要求。

扩展格式检查发现：真实旧 MOBI 带有原生 NCX 目录，当前导入会漏掉；真实 AZW3 转换副本的 EPUBCheck 也发现版本声明与 HTML 元素不兼容。两项均保留为未完成，后续必须通过原目录保留和标准 EPUB 导出验证。可用 `scripts/verify_app.py --sample /path/to/local/book` 添加本机真实样本，样本和内容不提交。

## 实现顺序与交付门槛

1. **配置与数据基础**：App 内服务设置、钥匙串、数据目录与迁移 / 备份，避免后续打包后回头搬数据。
2. **桌面宿主**：真正的主窗口、菜单、原生文件导入、进程生命周期、受保护的后端通道，沿用现有阅读模块。
3. **复杂教材增强**：持久化 MinerU 任务与缓存、区块映射、完整对象复制、目录与交叉引用、可导出重排内容。
4. **书内学习**：书内检索、此前知识约束、带出处的回答与回顾；补全取消、流式输出和错误恢复。
5. **安装与完整验收**：打包全部必要运行组件，验证主窗口 / 掌上窗口 / 导入 / 设置 / 退出重启；发布匿名资料与可安装构建。

这些步骤是依赖顺序，不是缩减范围。完成上述全部需求并有相应证据后，才能把完整产品标记为交付。

## 服务配置的边界

模型接口目前采用 Chat Completions 兼容协议。配置保存不发送书籍，连接测试仅发送一句测试文字；发问时按现有来源规则发送选段、附近内容与近期对话。保存设置影响后续请求，不改变已发出的请求。

MinerU 云 API v4 与本地 HTTP 服务是不同协议。本轮设置对应云 API v4 的 `vlm` / `pipeline`。当前官方公开文档提供任务创建与按任务 ID 查询，没有通用个人 Token 的无任务验证接口；因此“检查配置”不冒充鉴权成功、不创建计费解析任务。接通任务后必须用真实结果确认。参考：[MinerU 官方 API 文档](https://mineru.net/apiManage/docs)。

开发兼容优先级：已保存的应用配置 > 进程环境变量 > `.env` > 默认值。应用内移除凭据后，不重新启用 `.env` 旧 Key。更换服务目标地址时，需要重新填写凭据或明确移除，避免把旧 Key 发送到新目标。

## 2.16 已落地的桌面基础

- `native/App.swift` 提供原生主窗口、菜单、文件选择与“打开方式”导入；掌上窗口复用 `Palm.swift`，由同一 App 管理。
- 安装版把书库与记录放到 Application Support，把 OCR 缓存放到 Caches。原型开发模式继续兼容原目录；HTTP 资源地址不随磁盘位置变化。
- `scripts/migrate_library.py` 复制并校验旧书库，验证引用与源文件稳定性，再启用目标目录；拒绝覆盖已有目标。已在个人复杂书库验证 5 本、1666 个文件，原目录保留。
- 桌面服务使用动态回环端口与随机会话，阻止无会话访问、外部 Origin 和私有目录枚举。主进程退出后服务会清理；书库锁阻止重复服务写入。
- `scripts/build_app.py` 打包 Python、OCR、字体、PDF.js 和所需转换工具，原生组件在构建时编译。`scripts/verify_app.py` 在隔离目录、仅包含随包工具的 PATH 下验证导入、OCR、资源、会话和重启持久化。

当前构建仍是产品开发中的可运行版本。完整交互与最终安装验收仍须完成；不能据此标记完整目标已交付。

## 2.17 已落地的 PDF 云增强

真实英文教材 6 页、中文教材 3 页与原创匿名扫描件 4 页完成 MinerU 解析。界面可选择页段 / 整本、暂停与继续，重启恢复保留云任务身份；解析结果映射到原 PDF，完整公式、表格文字和原图取用可用。浏览器自动化验证不等于已完成全部原生窗口验收。

普通划词仍沿用原生文字层 / 本机 OCR 和保守校正；字符与区块映射现已接入原生 PDF / 扫描 OCR；低可信结果回退。最终安装与原生交互验收继续执行。

## 2.18 已落地的书内知识与选区校正

本机全文索引覆盖 EPUB、TXT、原生 PDF 与已增强扫描页；编号引用提供候选预览、跳转和返回。AI 默认检索当前位置之前的资料，每条回答保存来源文字与位置快照；支持逐段显示、停止和保留部分回答。普通 PDF 划词保持原几何，对可信区块执行字符映射，低可信部分保留原文。

实际复杂书库已完成索引；真实模型在复杂教材中使用六段此前资料并返回引用。扫描页覆盖和语义检索仍有明确边界，不将这些结果等同于全书知识依赖推理。最终安装与原生交互验收继续完成。

## 2.19 已落地的导出与数据管理

EPUB / TXT / 增强 PDF 导出已接入，MathML、表格、插图、原页标记与返回原 PDF 均有回归；真实教材发现的不可渲染公式会改用原图。应用内备份在校验后等待明确确认，下次启动才替换目录；恢复前书库保留，可回到之前的库。凭据与服务配置不随书库恢复而覆盖。

真实复杂书库 5 本、1668 个文件、约 118 MB 备份完成隔离恢复，原始书库校验保持一致。此轮继续验证原生保存面板、受管理重启、掌上与主窗口全流程；文本章节手工调整和图像答疑仍需完成，不能把导出 / 备份局部通过当成整个产品已验收。

## 2.20 的兼容性验收补充

## 2.21 的章节与原图验收

手工目录按不可变版本保存，位置由原文字符锚定；跨窗口旧版本被拒绝，解析开关保留手工结果。公式 / 表格按完整对象取用，扫描 OCR 漏表时透明对象锚点仍能参与划选。图像答疑支持明确的模型能力与每次附图选择，图像按书籍保存并纳入备份；来源不能指向外部地址或其他书籍。

实际 Chromium、源码、真实模型样本、原生窗口与冻结包已按本轮范围通过，0.5.0 已安装。原生鼠标事件复制的公式、表格和 PNG 直接核对系统剪贴板；附件随原生重启恢复。重复选段、Unicode 边界和跨列阅读顺序也已加入检查；不将章节序号、物理纵坐标或图片能上传等同于准确定位和正确理解。完整交付仍须对照上表完成最终审计，后台组合键的离焦行为等不能只以注册成功替代。
