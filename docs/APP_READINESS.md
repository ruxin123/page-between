# 从阅读原型到可交付的 macOS App

目标是交付可安装、可独立运行、可持续使用的桌面阅读产品。网页原型通过某项测试，不等于整个 App 已经交付；下表保留所有已提出的功能与验收要求。

## 不适合直接搬进 App 的地方

| 当前原型做法                         | 用户会遇到的问题                                     | 改造方向                                                                                  |
| ------------------------------------ | ---------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 编辑 `.env` 配置服务                 | 不符合普通 App 的使用方式；容易误删配置              | 设置分为阅读外观、AI 答疑、文档解析；密码输入只用于替换，留空保留，移除需明确操作         |
| 所有模型状态只表示“配过了”           | 地址正确不等于模型有权限，Token 保存不等于云任务可用 | 区分未配置、配置完整、检查失败与实际连接成功；测试草稿不自动保存                          |
| 凭据存在项目文件                     | 被打包、截图或分享代码时易误带                       | 新配置使用 macOS 钥匙串，普通设置单独保存；旧 `.env` 只做开发兼容，用户主动保存时迁移凭据 |
| 书库与进度写在源目录                 | `.app` 资源可能只读；升级会覆盖或分散数据            | 迁到 Application Support；缓存放 Caches；先验证并备份，再迁移；不得静默丢弃原书库         |
| 固定端口 + 终端启动本地 HTTP 服务    | 端口冲突、关窗残留、用户不知服务是否还在             | 桌面主进程管理后端生命周期；动态端口与会话认证；关闭 / 重启 / 单实例有明确行为            |
| 首次运行编译 Swift，要求安装外部工具 | 普通 Mac 无法开箱使用                                | 构建阶段编译并随包分发；后端与必要运行库随包；可选转换能力清楚报告                        |
| 上传整份文件到本机 HTTP 接口         | 大文件内存占用、原生拖放和文件权限体验差             | 原生导入面板 / 拖放，受控导入队列，流式复制与重复检测；外部磁盘离线状态可恢复             |
| 线程内任务 + 页面轮询                | 退出丢任务，失败记录不完整，无法取消                 | 持久化任务阶段、输入 / 输出与重试信息；恢复与取消有明确状态；进度推送给窗口               |
| 整段 AI 回答 + 无取消                | 等待时间长，用户无法终止错误请求                     | 可取消与超时，逐段回答；请求使用开始时的配置快照；输出仍经安全排版                        |
| 附近文字来自当前文本片段             | 不能可靠理解跨章定理关系                             | 统一书籍块、字符 / 页码锚点、术语与交叉引用索引，检索结果附来源                           |
| 原型侧重视觉页面                     | 权限、磁盘满、离线、升级、崩溃没有完整出口           | 用户可理解的错误与恢复动作；诊断单独显示、自动遮蔽凭据与书籍内容                          |
| 浏览器快捷键 / 打开方式              | 与系统及阅读器行为冲突                               | App 菜单、原生窗口事件与可发现的快捷键；验证主 / 掌上窗口焦点和后台翻页                   |
| 依赖源码运行验证                     | 无法证明安装包可独立工作                             | 干净环境、禁用开发 PATH、断网阅读、重启保留数据、大书回归、签名和安装验证                 |

## 实现顺序与交付门槛

1. **配置与数据基础**：App 内服务设置、钥匙串、数据目录与迁移 / 备份，避免后续打包后回头搬数据。
2. **桌面宿主**：真正的主窗口、菜单、原生文件导入、进程生命周期、受保护的后端通道，沿用现有阅读模块。
3. **复杂教材增强**：持久化 MinerU 任务与缓存、区块映射、完整对象复制、目录与交叉引用、可导出重排内容。
4. **书内学习**：书内检索、此前知识约束、带出处的回答与回顾；补全取消、流式输出和错误恢复。
5. **安装与完整验收**：打包全部必要运行组件，验证主窗口 / 掌上窗口 / 导入 / 设置 / 退出重启；发布匿名资料与可安装构建。

这些步骤是依赖顺序，不是缩减范围。完成上述全部需求并有相应证据后，才能把完整产品标记为交付。

## 服务配置的边界

模型接口目前采用 Chat Completions 兼容协议。配置保存不发送书籍，连接测试仅发送一句测试文字；发问时按现有来源规则发送选段、附近内容与近期对话。保存设置影响后续请求，不改变已发出的请求。

MinerU 云 API v4 与本地 HTTP 服务是不同协议。本轮设置对应云 API v4 的 `vlm` / `pipeline`。当前官方公开文档提供任务创建与按任务 ID 查询，没有通用个人 Token 的无任务验证接口；因此“检查配置”不冒充鉴权成功、不创建计费解析任务。接通任务后必须用真实结果确认。参考：[MinerU 官方 API 文档](https://mineru.net/apiManage/docs)。

开发兼容优先级：已保存的应用配置 > 进程环境变量 > `.env` > 默认值。应用内移除凭据后，不重新启用 `.env` 旧 Key。更换服务目标地址时，需要重新填写凭据或明确移除，避免把旧 Key 发送到新目标。

## 2.16 已落地的桌面基础

- `native/App.swift` 提供原生主窗口、菜单、文件选择与“打开方式”导入；掌上窗口复用 `Palm.swift`，由同一 App 管理。
- 安装版把书库与记录放到 Application Support，把 OCR 缓存放到 Caches。原型开发模式继续兼容原目录；HTTP 资源地址不随磁盘位置变化。
- `scripts/migrate_library.py` 复制并校验旧书库，验证引用与源文件稳定性，再启用目标目录；拒绝覆盖已有目标。已在个人复杂书库验证 5 本、1666 个文件，原目录保留。
- 桌面服务使用动态回环端口与随机会话，阻止无会话访问、外部 Origin 和私有目录枚举。主进程退出后服务会清理；书库锁阻止重复服务写入。
- `scripts/build_app.py` 打包 Python、OCR、字体、PDF.js 和所需转换工具，原生组件在构建时编译。`scripts/verify_app.py` 在隔离目录、仅包含随包工具的 PATH 下验证导入、OCR、资源、会话和重启持久化。

当前构建仍是产品开发中的可运行版本。MinerU 云任务、全书知识检索与定理引用、重排导出、应用内备份恢复及完整交互验收仍须完成；不能据此标记完整目标已交付。
