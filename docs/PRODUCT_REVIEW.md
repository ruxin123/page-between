# 产品与 UI 评审指南

## 先阅读

1. [README](../README.md)：目标、运行方式、匿名截图、能力边界。
2. [功能说明](FEATURES.md)：各页面职责、阅读模式与取用流程。
3. [验证记录](../QA.md)：区分已验证与待验证能力。

运行 `python server.py --demo`，使用生成的演示库即可评审；不需要真实书籍或 API Key。公开截图全部使用自编资料，评审中也请继续使用示例数据。

## 建议走查

| 场景             | 需要观察的行为                                               |
| ---------------- | ------------------------------------------------------------ |
| 找书与开始阅读   | 书库 / 书架是否容易区分；继续阅读与封面入口是否明确          |
| 导入两种格式     | EPUB 与 TXT / PDF 的解析默认值是否好理解；开关说明是否适量   |
| 连续读几个屏幕页 | 位移、节奏、阴影、跨章衔接是否舒适；快速多次翻页是否造成迷失 |
| 改字体和窗口     | 当前文字是否仍能找到；页码变化是否让人理解                   |
| 查看章节与返回   | 目录是否易找；跳转和返回是否维持位置                         |
| 选中内容提问     | 选区菜单是否挡字；草稿出处是否清楚；关闭后能否继续读         |
| 看固定版 PDF     | 缩放、滚动、文字准备状态和页码含义是否清楚                   |
| 掌上阅读         | 小窗层级、字号密度、键盘操作、设置和关闭入口是否协调         |

优先检查桌面常见宽度与 `344×560`、`280×440` 小窗。截图中的示例正文只用于评审排版，不能据此判断某本教材的识别准确率。

## 可直接交给评审 AI 的提示词

```text
请作为个人阅读产品的产品专家与 macOS UI 评审者审查本仓库。

先阅读 README.md、docs/FEATURES.md、QA.md 以及 docs/screenshots/ 中的实际界面。
如果可以运行环境，请启动 python server.py --demo，按本文的场景逐项走查。

产品以个人使用、小说与严肃教材为主。当前重点是阅读，不要默认扩展为通用知识管理或大型 AI 工作台。
EPUB 保留原有结构，PDF 保留原版面并补充识别能力；二者不必强行采用完全相同的阅读排版。
AI 回答目前未实现，提问只是草稿，请把这一边界与交互质量分开评价。

请按优先级给出：
- 具体问题：发生在哪个页面、什么操作之后。
- 对读者的影响：增加了什么理解、操作或阅读负担。
- 证据：截图位置或可以重复的操作路径。
- 建议改动：优先提供较小而完整的改法。
- 验收方式：如何判断改动确实改善体验。

请单列 P0/P1 阻碍与 P2 细节。说明哪些结论来自实际走查，哪些仅来自截图或推测。
最后给出下一轮最值得完成的三个改动，不要只列风格形容词，也不要未经验证就重做整个界面。
```

评审输出可以整理为问题表：优先级、页面、触发步骤、影响、证据、改法、验收。请避免把新的长期功能需求和当前缺陷混在一起。
