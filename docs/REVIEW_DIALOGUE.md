### 需要校正的源码判断

1. **图标不是缺少圆角规范。** 基线 `layout.css` 的 `svg` 已有 `stroke-width: 1.6`、`stroke-linecap: round`、`stroke-linejoin: round`。本轮改为 1.75 并把属性写进 SVG，以便独立复用；这属于一致性强化。
2. **⌘K、⌘B 和等宽页码并非缺失。** 基线 `handleKeydown` 已处理目录与书签，`#page-label` 也已有 `tabular-nums`。本轮补充其他位置与快捷键，并修复真实走查发现的「空格键吞掉按钮激活」问题。
3. **没有找到 smooth resize 的调用。** 基线 `PageLayout` 用真实 DOM 多栏和 `translateX`，窗口改变通过 `configureTextLayout` 与 `captureAnchor / restoreAnchor` 重排；不存在你描述的 `relayout()` 或 resize 中的 `scrollTo({behavior:"smooth"})`。如果实际有抖动，请提供窗口尺寸、格式、章节与复现过程。
4. **不采用示例 B 的比例式定位。** 原方案已经定位到段落和字符。`index / (pages - 1)` 在插图、跨页长段落和字体变化后无法保证回到同一句话；示例也没有覆盖原生 EPUB、选区几何、动画清理和现有构造器调用方。直接替换会回退现有能力。
5. **书库并非无限铺开。** 基线 `.app-view` 已限制为 1150px；本轮设为最多 1280px 并调整间距。可以讨论更合适的密度，但应把已有约束与审美偏好分开描述。
6. **⌥Space 不是已有的小窗呼出键。** 当前原生代码注册的是小窗运行时的 `⌃⌥⌘← / →` 翻页。尚未实现全局呼出，不会先写上不可用的快捷键；离焦翻页仍需进一步复核。

### 暂缓的设计建议

- **React / Tailwind / Framer Motion 整体迁移**：原生节点复用已解决本轮网格问题。仅凭脚本行数不足以证明整体迁移的收益，迁移还需重新验证 iframe 选区、阅读位置和小窗同步。
- **鼠标静止后顶栏降至 15% 透明度**：可能使键盘用户和低视力读者找不到控件，也会让界面在被动阅读时反复改变。先保留明确的专注模式；若后续引入自动隐藏，需要保证焦点、悬停、弹窗和辅助技术能可靠恢复。
- **统一降为 18px / 1.85**：是值得比较的排印方案，但不是已证实的缺陷。本轮保留个人字号与行距偏好，未重置已保存设置。希望用中英文、教材 / 小说的长时间阅读比较来决定默认值。
- **全局 Command Palette、OCR 全文搜索、边缘吸附和原生材质**：属于后续功能，需要明确数据覆盖、系统快捷键冲突与验收条件；本轮没有用模拟结果冒充这些能力。

## 2026-10-15 · 第二轮反馈收尾（前端 2.14）

本轮以 `069c9e0` 为基线。已核实并处理三项缺陷：

- **任务恢复**：新任务替换同书旧任务，同时同步书籍的 pending / ready / error；关闭增强后也能结束等待状态。任务面板按书聚合，以当前书籍状态为准，旧失败记录不会覆盖成功结果。原队列已有 100 条上限，问题并非无限增长，而是旧记录被当作当前告警。补上「重新解析」「书籍设置」入口，未进入任务队列的书籍也能显示。
- **字符边界**：将测量统一到 `characterRect`，供分页和滚动定位共同使用。节点长度边界前进到下一个非空节点，段落末尾测量最后一个字符；不可见前导空白仍回退到段落起点，避免示例补丁中“无矩形就测段尾”引入新的跳转。
- **键盘与撤销焦点**：过滤前捕获焦点；移出常读后优先选择相邻下一张可见卡片，再选择上一张，结果为空时聚焦空状态操作。通知显式保留原星标作为撤销目标，等待保存时使用 ARIA 忙碌状态以保留焦点，且不把焦点送回隐藏控件，也不覆盖用户等待期间移到别处的焦点。

封面双重书脊内阴影、学习类长标题字号回弹、夜间主题预览勾选颜色也已修正。加入任务失败后重试成功、关闭增强、跨内联节点 / 段尾定位、相邻卡片焦点和重复撤销防护的回归测试。

对于“3px 阈值跳过前导空白首行”，目前仍缺少最小复现。该阈值用于避开被视口裁切的行，常规掌上正文另有 18px 内边距；仅根据两处数字不能断定首行必然被跳过。本轮保留这一策略，后续若遇到实际锚点漂移，将保留样本和窗口尺寸再定位。

小窗常驻显隐是合理的下一阶段功能建议，但这次先结束视觉打磨循环。我们也不把“准商业级”观感评级视为已经完成正式产品的稳定性验证。

## 2026-10-16 · App 内服务配置与交付边界（前端 2.15）

本轮源自用户的新要求：模型与 MinerU 配置必须在 App 内完成，最终交付完整 macOS 产品。我们先落实独立设置分区、保存 / 连接测试、凭据保留 / 替换 / 移除、钥匙串保管，并保留旧开发配置兼容。完整需求没有缩减为设置页，见 `APP_READINESS.md` 的逐项验收表。

请后续评审关注三处具体边界：

- `ui/settings.mjs` 不受阅读偏好重绘影响；切换设置分类不丢草稿。模型连接测试使用当前表单但不自动保存，也不附带任何书籍内容。
- 配置中的 Key 只写入 macOS 钥匙串。普通设置只有随机引用；替换失败不破坏旧配置。更换服务目标地址时不默认转交旧凭据。
- MinerU 配置的“检查”不是虚假的连接成功。当前公开云 API 文档没有通用个人 Token 的无任务验证接口，且现有日常 PDF OCR 仍是本机实现。界面明确写出云任务尚未接入；真实任务接通后再升级这一状态。

此轮仍沿用现有 ES Modules、Python 与少量 Swift。还没有证据说明更换 React 或整体重写原生阅读器会改善当前核心问题，因此先补应用运行、数据目录、任务恢复和发行链路。欢迎指出这一判断在具体功能上遇到的阻碍，最好附可复现样本和失败操作。
